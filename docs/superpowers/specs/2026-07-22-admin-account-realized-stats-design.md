# 管理帳號已實現損益統計設計

日期：2026-07-22

## 目標

在管理員頁面的每個帳號卡片中，除了既有的未平倉損益，直接顯示與交易紀錄頁「全部」區間一致的已實現交易統計：

- 已實現損益
- 已實現報酬率
- 獲利賣出筆數與虧損賣出筆數
- 勝率
- 涉及股票檔數與股票交易筆數

## 資料來源與載入方式

管理頁目前會在帳號清單完成後，背景載入所有持倉與行情。新增的交易統計也放在背景階段，以一次 Supabase 查詢取得統計所需的最小欄位：`id`、`user_id`、`stock_code`、`trade_type`、`total_amount`、`profit`。

交易資料不載入附件、筆記或其他未使用欄位，避免不必要的傳輸。帳號清單本身仍優先顯示，不等待持倉、行情或交易統計完成。

## 共用統計模型

新增一個不依賴 React 或 Supabase 的純函式，輸入標準化交易陣列，回傳：

- `realizedProfit`：所有具有有效 `profit` 的賣出交易損益總和。
- `realizedCostBasis`：每筆有效賣出交易的 `totalAmount - profit` 加總。交易 RPC 中 `totalAmount` 是扣除賣出費用後的實收金額，而 `profit = totalAmount - 成本`，因此可反推出實際賣出持股成本。
- `realizedReturnPct`：`realizedProfit / realizedCostBasis * 100`。沒有正數成本時回傳 `null`。
- `winCount`：`profit > 0` 的賣出筆數。
- `lossCount`：`profit < 0` 的賣出筆數。
- `winRatePct`：`winCount / (winCount + lossCount) * 100`。沒有勝敗交易時回傳 `null`；損益為零的賣出不列入分母。
- `stockCount`：買入或賣出交易涉及的不重複股票代號數。
- `tradeCount`：買入與賣出交易總筆數；入金、出金不計入。

交易紀錄頁既有的已實現損益與勝敗統計也改用這個純函式，避免管理頁與圖 2 形成兩套公式。

## 管理頁資料整理

背景查詢完成後，把資料標準化並以 `user_id` 分組。React 使用 `useMemo` 一次建立每個帳號的統計映射，帳號卡片只做 O(1) 查找，不在每次渲染時重新掃描所有交易。

交易統計另外保存載入狀態與錯誤狀態：

- 載入中：顯示「已實現統計讀取中」。
- 成功但沒有賣出紀錄：金額顯示 `NT$ 0`，已實現報酬率與勝率顯示 `--`。
- 查詢失敗：顯示「已實現統計暫時無法讀取」，不把錯誤誤表示成零損益。

## 帳號卡片呈現

在既有現金與未平倉損益下方新增兩行：

```text
📈 已實現：+NT$ 17,273（+11.2%）
🏆 勝 11・敗 50・勝率 18.0%・44 檔／184 筆
```

顯示規則：

- 已實現損益與已實現報酬率皆保留一位小數百分比。
- 勝率保留一位小數。
- 正數採台股獲利紅色，負數採虧損綠色，零值採中性色。
- 小螢幕允許統計內容自然換行，不擠壓帳號名稱、徽章或操作按鈕。
- 既有未平倉損益、庫存市值與所有管理操作保持不變。

## 交易紀錄頁呈現

圖 2 的「區間已實現損益」、勝敗筆數、檔數與交易筆數維持原版面與日期／搜尋篩選行為，只將內部統計改用共用純函式。交易紀錄頁不新增勝率或已實現報酬率版面，這兩個新百分比只依需求加在管理帳號卡片。

## 測試策略

先為共用純函式建立失敗測試，再實作功能。測試至少涵蓋：

1. 多筆獲利與虧損賣出可正確加總已實現損益、成本、報酬率與勝率。
2. 損益為零的賣出計入交易筆數，但不計入勝率分母。
3. 買入、入金與出金不會影響已實現損益或勝敗筆數。
4. 股票檔數只計算不重複的股票代號。
5. 沒有有效賣出交易時，兩個百分比回傳 `null`。
6. 缺失或無效數字不產生 `NaN`，也不污染其他有效統計。
7. 交易紀錄頁的區間及搜尋篩選仍只統計可見交易。

完成後執行針對性測試、完整測試腳本、ESLint 與正式建置，並檢查管理頁在桌面與行動版的文字換行。
